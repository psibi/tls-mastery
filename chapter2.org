* TLS Connections

- You can use a tool like netcat to send arbitrary traffic. TLS
  complicates this process.
- If I use netcat to connect to a TLS-wrapped port, I'll get binary
  TLS in my text-only client. I need my client to handle TLS for me.
- OpenSSL includes the *s_client* subcommand for creating and
  debugging TLS-wrapped network connections.

* Connecting to Ports

- Clients connect to network ports via direct TLS connections, TLS
  connections with CR/LF handling etc.

** Connecting versus Debugging

- The *s_client* command was written for debugging TLS connections.
- When it discovers invalid certificats, it defaults to accepting them
  and continuing on. If you're relying on OpenSSL to expose TLS
  problems, add the *-verify_return_error* flag to all of your
  s_client commands.

** Line Feeds, Carriage Returns, and Newlines

- The different way of handling newline across OS applies also to text
  protocol.
- Modern OpenSSL uses either the *-connect* or the *-crlf* options to
  connect to network ports. The connect option treats ENTER as
  carriage return with a line feed, while crlf trates ENTER as a
  crarriage return.

** TLS Dedicate TCP ports

- HTTPS uses port 443
- The *-connect* argument tells *s_client* to create a TLS client to
  the given host and port.

#+begin_src sh :exports both :eval never-export :results verbatim
openssl s_client -verify_return_error -connect imap.gmail.com:995
#+end_src

* Opportunistic TLS

- In some protocols, a client can request that a server use TLS and
  servers can request clients upgrade to TLS.
- This opportunistic TLS was ideal for universal protocols like email,
  where everyone had a server and they couldn't all simultaneously
  upgrade.
- Opportunistic TLS is often called *STARTTLS*.
- Openssl supports *-starttls* option.

* Connection commands

- The *s_client* session remains open until you terminate it.
- Entering a *Q* cleanly closes the TLS connection.
- Entering a *k* sends a TLS 1.3 key update.
- Entering a *K* sends an update and requests one in return.

** DTLS

- You can use *s_server* subcommand from OpenSSL to interact with
  DTLS.


* Silencing s_client

- *-quiet* flag to slience everything except a summary of the
  certificate chain.

#+begin_example
openssl s_client -quiet -verify_return_error psibi.in:443
#+end_example

* Specific TLS Versions

#+begin_example
openssl s_client -brief -ssl3 -crlf www.psibi.in:443
#+end_example

* Choosing Ciphers

- The *-cipher* option lets you specify TLS 1.2 options.
- The *-ciphersuite* lets you specify TLS 1.3 ciphers.
