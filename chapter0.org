* Introduction

- TLS encrypts a network connection during transit. That's it.

* TLS, SSL and Versions

- A digital certificate is a collection of carefully formatted
  information that identifies an entity, digitally signed ay a
  certificat authority.
- A certificate signed by itself is called a self signed certificate.
- Secure Socket Layer or SSL was an early transport layer security
  protocol. Netscape created the primordial SSL in 1994 and let people
  test it. The earlier version had flaws. So Netscape released version
  2 in 1995 and version 3 in 1996.
- The IEFT released version 1 of Transport layer security or TLS
  in 1999. It's a direct descendant of SSL version 3. The name was
  changed for political reasons.
- TLS 1.1 escaped in 2006, 1.2 in 2008 and 1.3 in 2018.
- As of 2020, all Internete sites sould prefer TLS version 1.3 falling
  back to 1.2 only if necessary.

* Why TLS?

- TLS is a generic protocol for wrapping individual TCP/IP
  connections. Where solutions like IPSec can taunnel and encrypt all
  traffic between two IP addresses, TLS encrypts only a single
  connection.
- TLS can be added to existing protocols comparatively simply.

* Using openssl

- Can create keypairs, digitally sign files, parse ASN.1 and X.509,
  generated randomish numbers and verify TLS certificates.
- Openssl command format:

#+begin_example
openssl subcommand flags
#+end_example

- *genrsa* subcommand creates RSA keys.
- *x509* subcommand copes with X.509 certificates.

Common flags:

- *-in* flags for input
- *-out* flags for output
- *-text* textual format

#+begin_src sh
openssl version
#+end_src

- Many OpenSSL commands are designed to feed into one another, like
  so:

#+begin_src sh :results verbatim
openssl s_client -showcerts -connect psibi.in:443 | openssl x509 -text -noout | head
#+end_src

- The *s_client* command servers as a TLS-aware netcat, negotiating a
  TLS connection with the host and port you specify.
- The *-showcerts* option displays the certificate information.
- The *-connect* lets you choose the target.
- We use the *x509* subcommand to say that we want human friendly
  output with the *-text* option.
- The *-noout* tells it skip showing the encoded certificate.
- The above command grabs a website's TLS certificate and displays the
  contents.

* The United States and FIPS

- Most organization in Canada and the United States must comply with
  the US Federal Information Processing Standards (FIPS), a set of
  cryptography requirements.
- The current standard is FIPS 140-3. It's often called as "FIPS 140".

* Applications and TLS

- Every application server configures TLS differently.
- This book focuses on the concepts so that you become competent to
  configure your application server properly.

* TLS versus DTLS

- TLS expects the network to handle packet delivery, including coping
  with any retransmissions and reording and so on. This means it runs
  only on TCP.
- Many UDP applications also need transport protection. Rather than
  invent a whole new protocol, people took TLS and added a state
  tracking system to handle all the netowrk accounting. This result is
  the Datagram Transport Layer Security (DTLS) protocol.
